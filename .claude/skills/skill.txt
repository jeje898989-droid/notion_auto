[대상 경로] /.claude/skills/route-request/SKILL.md
[역할] 모든 요청의 진입점 — 트리거 키워드 인식 및 라우팅

# 개요
1. frontmatter
   - name, description (트리거: "키워드: 내용" 형식의 모든 입력)
2. 입력 파싱 규칙
   - 형식: <키워드>: <내용>  (구분자 ":" / "：" 허용, 앞뒤 공백 무시)
   - 키워드 대소문자·공백 정규화, 별칭(alias) 매칭
3. 트리거 조회
   - workspace/cache/trigger-map.json 사용, 캐시 없음/오래됨/미스 시 notion-analyst로 갱신
4. 분기
   - 작업 유형 = 등록 → notion-register
   - 작업 유형 = 조회 → notion-task-check
   - 작업 유형 = GWS → gws-action
5. 예외 처리
   - 키워드 없음 / 미등록 키워드 / 복수 매칭 → 등록된 키워드 목록 보여주고 질문
6. 예시
   - "개인: 친구와 카페약속" → 개인일정 DB / 등록
   - "확인: 오늘 마감" → 업무일정 DB / 조회

[대상 경로] /.claude/skills/notion-register/SKILL.md
[역할] 트리거로 결정된 DB에 항목을 등록하는 워크플로

# 개요
1. frontmatter: name, description
2. 입력: route-request 결과 (대상 DB, 내용 원문)
3. 내용 → 속성 추출
   - 제목, 날짜/시간, 장소, 분류 등을 notion-schema.md 의 대상 DB 속성에 매핑
   - 날짜 미기재 시 처리 규칙 (질문 / 기본값)
4. 확인 단계
   - "개인일정 DB에 [제목 / 날짜 / 시간]으로 등록할까요?" 형식으로 한 번에 확인
5. 승인 후
   - notion-writer 호출 → 페이지 링크 보고
   - 트리거에 후속 GWS 지정 시 → 실행 계획 생성 후 gws-action 제안

==================================================================

[대상 경로] /.claude/skills/notion-task-check/SKILL.md
[역할] 조회형 트리거("확인: 오늘 마감" 등)의 표준 워크플로

# 개요
1. frontmatter: name, description
2. 입력 해석
   - route-request 결과(대상 DB) + 내용에서 기간·상태·담당자 추출
   - 대상 DB 미지정 조회 시: 트리거 DB에 등록된 조회 가능 DB 전체 대상
3. 절차
   - notion-analyst 호출 → 보고서 수신 → 표 형식 요약 보고
   - 후속 작업 제안 → 선택 시 workspace/approvals/ 에 계획 파일 생성
4. 승인 질문 형식: 무엇을 / 누구에게 / 어떤 파일로
5. 승인 후 gws-action 으로 인계

==================================================================

[대상 경로] /.claude/skills/gws-action/SKILL.md
[역할] 승인 계획을 받아 GWS 작업을 실행하는 워크플로

# 개요
1. frontmatter: name, description (트리거: GWS 유형 키워드, 계획 승인)
2. 입력: workspace/approvals/<계획ID>.json
3. 절차
   - 계획 검증 → 템플릿 선택(templates/) → 내용 생성 → gws-executor 호출
4. 사용자 보고: 메일 초안/문서/일정 링크, 실패 항목과 원인
5. 예외: 인증 만료, 권한 부족, 수신자 누락 시 중단 후 재확인
