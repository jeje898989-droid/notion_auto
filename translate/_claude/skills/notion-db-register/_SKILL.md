# notion-db-register

요청에 맞는 Notion DB에 항목을 등록한다.

> **사용자 승인 없이 절대 등록하지 않는다.**

## 입력

- 사용자의 요청 원문.

## 1단계 — 분류 및 대상 DB 결정

- rules 파일(`nt-personal`, `nt-work`, `nt-study`) 기준으로 항목을 분류한다. 각 파일에 대상 DB, 분류 기준, 속성 매핑이 정의되어 있다.
- 둘 이상의 DB에 해당할 수 있으면 → 사용자에게 질문. **추측하지 않는다.**

## 2단계 — 내용을 속성으로 나누기

1. 대상 DB의 rules 파일과 `config/notion-schema.md`의 속성 매핑을 사용한다.
2. 내용을 DB 속성별로 나눈다:
   - 제목: 핵심 행동/대상 (예: `친구와 카페약속`).
   - 날짜/시간: 상대 표현을 절대 날짜로 변환 (오늘 = 세션 날짜). 시간이 있으면 → datetime.
   - select 속성 (분류, 상태, 우선순위): 기존 옵션에만 매핑, 없으면 기본값 적용.
   - 장소, 참석자 등 맞는 속성이 없는 내용 → `메모`.
3. `config/notion-schema.md`의 DB 기본값을 적용한다.
4. 필수 속성이 없으면 (예: 날짜) → 사용자에게 질문.

## 3단계 — 확인 (승인 관문)

한 번의 메시지로 전부 보여주고 기다린다:

```
[개인 일정] DB에 다음과 같이 등록할까요?
| 속성 | 값 |
|---|---|
| 일정 | 친구와 카페약속 |
| 날짜 | 2026-11-15 14:00 |
| 분류 | 약속 |
| 상태 | 예정 |
| 메모 | 장소: 강남 |
```

- 승인 → 4단계. 수정 → 고친 뒤 다시 확인. 취소 → 중단, 아무것도 기록하지 않음.

## 4단계 — notion-writer로 등록

- `notion-writer` 서브에이전트에 전달: 대상 data source, 승인된 속성값, 내용 원문.
- 생성된 페이지 링크를 사용자에게 보고한다.

## 5단계 — 후속 GWS (있는 경우)

- 사용자가 후속 작업(캘린더 일정, 메일 등)을 요청했거나 명확히 어울리면 (예: 시간이 정해진 약속 → 캘린더) 제안한다.
- 사용자가 동의하면 `workspace/approvals/README.md` 규격에 따라 `workspace/approvals/`에 계획 파일을 생성(`status: pending`)한 뒤 `gws-execute`로 위임한다.

## 금지

- 승인 없는 등록.
- rules 파일에 정의되지 않은 DB에 쓰기.
- select 옵션 임의 생성 또는 DB 스키마 변경.
